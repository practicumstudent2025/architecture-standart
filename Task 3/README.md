# Задание 3: Концептуальная архитектура MVP открытия депозитов

## Описание задания

В рамках третьего задания была создана концептуальная архитектура MVP для открытия депозитов онлайн в формате ADR (Architecture Decision Record). Архитектура учитывает все требования из предыдущих заданий и технические ограничения банка "Стандарт".

## Структура решения

### 1. ADR (Architecture Decision Record)
- **Файл**: `ADR-MVP-Deposit-Architecture.md`
- **Описание**: Подробный документ архитектурного решения, включающий:
  - Контекст и проблемы текущего состояния
  - Архитектурные принципы и решения
  - Альтернативы и их оценку
  - План внедрения и команды разработки
  - Use Cases для всех основных сценариев

### 2. Диаграммы в модели C4

#### Диаграмма контекста
- **Файлы**: 
  - `Context-Diagram.drawio` - исходный файл draw.io
  - `Context-Diagram.html` - HTML-версия для просмотра
- **Описание**: Высокоуровневое взаимодействие между системой и внешними акторами

#### Диаграмма контейнеров
- **Файлы**:
  - `Container-Diagram.drawio` - исходный файл draw.io
  - `Container-Diagram.html` - HTML-версия для просмотра
- **Описание**: Детальная архитектура с разделением на слои и детализацией интернет-банка и АБС

## Ключевые архитектурные решения

### 1. Многослойная архитектура
- **Presentation Layer**: Веб-сайт и интернет-банк
- **Integration Layer**: API Gateway и система очередей
- **Business Logic Layer**: Сервисы депозитов и ставок
- **Data Layer**: Базы данных и кэширование
- **External Systems**: Внешние системы банка

### 2. API Gateway
- Централизованная точка входа
- Защита от перегрузки АБС
- Аутентификация и авторизация
- Кэширование и маршрутизация

### 3. Асинхронная обработка
- Система очередей RabbitMQ
- Снижение нагрузки на критические системы
- Надежная обработка заявок

### 4. Кэширование
- Redis для справочных данных
- Ускорение загрузки ставок
- Снижение нагрузки на базы данных

### 5. Мониторинг
- Prometheus + Grafana
- Контроль производительности
- Обеспечение 99.9% доступности

## Технологический стек

### Существующие технологии (переиспользование)
- **Базы данных**: MS SQL, Oracle
- **Платформы разработки**: .NET Framework 4.5, ASP.NET MVC
- **СМС-функционал**: Существующая система
- **Системы безопасности**: Текущие механизмы аутентификации

### Новые технологии
- **API Gateway**: .NET Core
- **Очереди**: RabbitMQ
- **Кэширование**: Redis
- **Мониторинг**: Prometheus + Grafana

## План внедрения

### Этап 1 (1-2 месяца): Подготовка инфраструктуры
- Развертывание API Gateway
- Настройка системы кэширования
- Настройка мониторинга
- Подготовка среды разработки

### Этап 2 (3-4 месяца): Разработка MVP
- Интеграция с интернет-банком
- Разработка функционала подачи заявок
- Интеграция с кол-центром
- Разработка системы уведомлений

### Этап 3 (5-6 месяцев): Тестирование и запуск
- Комплексное тестирование
- Пилотный запуск
- Мониторинг производительности
- Обучение персонала

## Критерии успеха

### Технические критерии
- Время отклика системы < 1 секунды
- Доступность системы 99.9%
- Успешная обработка 95% заявок
- Отсутствие перегрузки АБС

### Бизнес-критерии
- Увеличение количества онлайн-заявок на 50%
- Сокращение времени обработки заявок на 70%
- Снижение нагрузки на бэк-офис на 30%
- Улучшение клиентского опыта

## Риски и митигация

### Высокие риски
1. **Перегрузка АБС**
   - **Митигация**: API Gateway с ограничением нагрузки, асинхронная обработка

2. **Проблемы с безопасностью**
   - **Митигация**: Шифрование трафика, аудит операций, разделение доступа

3. **Несовместимость технологий**
   - **Митигация**: Использование совместимых технологий, поэтапное внедрение

### Средние риски
1. **Сложность интеграции**
   - **Митигация**: Поэтапное внедрение, тестирование на каждом этапе

2. **Проблемы с производительностью**
   - **Митигация**: Кэширование, оптимизация запросов, мониторинг
