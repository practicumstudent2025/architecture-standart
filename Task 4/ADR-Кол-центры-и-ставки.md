### **Название задачи:** 
Интеграция кол-центров с системой ставок для поддержки пожилых клиентов банка "Стандарт"

### **Автор:**
Команда цифровой трансформации банка "Стандарт"

### **Дата:**
2024-01-15

### **Функциональные требования**
Опишите здесь верхнеуровневые Use Cases. Их нужно оформить в виде таблицы с пошаговым описанием:

|**№**|**Действующие лица или системы**|**Use Case**|**Описание**|
| :-: | :- | :- | :- |
|1|Сотрудник кол-центра|Консультация клиента по ставкам|Сотрудник получает звонок от клиента, открывает систему кол-центра, видит актуальные ставки по депозитам, консультирует клиента по условиям и может помочь с подачей заявки|
|2|Сотрудник кол-центра|Помощь в подаче заявки|Сотрудник помогает клиенту подать заявку на депозит через телефон, вводит данные клиента в систему, получает подтверждение и сообщает клиенту о статусе|
|3|Система кол-центра|Получение актуальных ставок|Система автоматически получает обновления ставок из центральной системы, обновляет локальную базу данных и уведомляет сотрудников об изменениях|
|4|Система партнерского кол-центра|Получение файлов со ставками|Система получает файлы со ставками через SFTP, обрабатывает данные и обновляет локальную базу, отправляет подтверждение о получении|
|5|Администратор системы|Управление передачей ставок|Администратор настраивает расписание передачи ставок, выбирает форматы файлов, управляет списком получателей и мониторит статус передачи|

**Детализация ключевых компонентов:**

1. **Система передачи ставок** - детализирована как контейнер с функциями:
   - Управление расписанием передачи
   - Форматирование данных для разных получателей
   - Шифрование и безопасная передача
   - Мониторинг статуса передачи

2. **Кол-центр банка** - детализирован как система с компонентами:
   - База данных ставок (локальная копия)
   - Интерфейс для сотрудников
   - Система уведомлений об обновлениях

3. **Партнерский кол-центр** - детализирован как внешняя система:
   - SFTP-сервер для получения файлов
   - Система обработки файлов
   - Локальная база данных ставок

#### Архитектурные принципы:

1. **Принцип безопасности** - шифрование всех каналов передачи данных
2. **Принцип надежности** - резервирование каналов и автоматическое восстановление
3. **Принцип совместимости** - использование существующих технологий кол-центров
4. **Принцип мониторинга** - полный контроль процесса передачи данных

#### Концептуальная архитектура:

**1. Уровень управления ставками (Rate Management Layer)**
- **Сервис ставок** - основная система управления ставками
- **Система передачи ставок** - координация передачи данных
- **Система мониторинга** - контроль процесса передачи

**2. Уровень интеграции (Integration Layer)**
- **SFTP-сервер** - безопасная передача файлов
- **API для кол-центра** - интеграция с внутренним кол-центром
- **Система уведомлений** - оповещения об обновлениях

**3. Уровень получателей (Recipients Layer)**
- **Кол-центр банка** - внутренняя система
- **Партнерский кол-центр** - внешняя система
- **Системы обработки файлов** - обработка полученных данных

#### Ключевые компоненты:

**Система передачи ставок**
- **Назначение**: Координация передачи ставок всем получателям
- **Функции**: Планирование, форматирование, шифрование, мониторинг
- **Технологии**: .NET Core, MS SQL

**SFTP-сервер**
- **Назначение**: Безопасная передача файлов партнерскому кол-центру
- **Функции**: Аутентификация, шифрование, логирование
- **Технологии**: OpenSSH, SFTP

**API для кол-центра**
- **Назначение**: Интеграция с внутренним кол-центром
- **Функции**: Передача ставок, уведомления, мониторинг
- **Технологии**: REST API, WebSocket

**Система мониторинга**
- **Назначение**: Контроль процесса передачи данных
- **Функции**: Отслеживание статуса, уведомления об ошибках
- **Технологии**: Prometheus + Grafana

#### Логика принятия решений:

1. **Использование SFTP для партнерского кол-центра** - из-за ограничений внешней системы
2. **API для внутреннего кол-центра** - для быстрой интеграции
3. **Шифрование файлов** - для обеспечения безопасности данных
4. **Автоматическое восстановление** - для обеспечения надежности
5. **Мониторинг процесса** - для контроля качества передачи

#### Технологический стек:

**Существующие технологии (переиспользование):**
- **Базы данных**: MS SQL, Oracle
- **Системы кол-центров**: Существующие платформы
- **Сетевые протоколы**: SFTP, HTTP/HTTPS
- **Системы безопасности**: Текущие механизмы

**Новые технологии:**
- **Система передачи ставок**: .NET Core
- **SFTP-сервер**: OpenSSH
- **API для кол-центра**: REST API
- **Мониторинг**: Prometheus + Grafana

### **Недостатки, ограничения, риски**

Подробно опишите здесь недостатки, ограничения и риски выбранного решения.

#### Высокие риски:

1. **Проблемы с безопасностью**
   - **Риск**: Передача чувствительных данных через внешние каналы
   - **Митигация**: Шифрование файлов, безопасные протоколы, аудит

2. **Перегрузка кол-центров**
   - **Риск**: Увеличение количества звонков после запуска
   - **Митигация**: Подключение партнерского кол-центра, автоматизация

3. **Проблемы с передачей данных**
   - **Риск**: Сбои в передаче ставок
   - **Митигация**: Резервирование каналов, автоматическое восстановление

#### Средние риски:

1. **Сложность интеграции**
   - **Риск**: Проблемы интеграции с существующими системами
   - **Митигация**: Поэтапное внедрение, тестирование

2. **Проблемы с производительностью**
   - **Риск**: Задержки в обновлении ставок
   - **Митигация**: Оптимизация процесса, мониторинг

#### Ограничения:

1. **Технологические ограничения**
   - Необходимость использования SFTP для партнерского кол-центра
   - Совместимость с существующими системами
   - Ограничения по скорости передачи файлов

2. **Бизнес-ограничения**
   - Требование быстрого обновления ставок
   - Необходимость поддержки пожилых клиентов
   - Ограничения по бюджету

3. **Архитектурные ограничения**
   - Использование существующих систем кол-центров
   - Безопасность передачи данных
   - Надежность процесса передачи

#### Недостатки решения:

1. **Сложность процесса**
   - Множество компонентов и интеграций
   - Необходимость координации команд
   - Сложность тестирования

2. **Зависимость от внешних систем**
   - Партнерский кол-центр
   - SFTP-сервер
   - Системы кол-центров

3. **Необходимость обучения персонала**
   - Новые процессы и системы
   - Изменение рабочих процессов
   - Дополнительные затраты
