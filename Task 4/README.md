# Task 4: Интеграция кол-центров с системой ставок

## Описание задачи

Менеджер проектов из команды цифровой трансформации занимается подготовкой дорожной карты проекта. Для этого ему нужно определить, в какой последовательности команды должны делать изменения в своих системах. Понять это поможет архитектура MVP, которую вы спроектировали ранее.

Также команда обнаружила проблему: большинство клиентов банка «Стандарт» — пожилые люди. Как только банк запустит маркетинговую кампанию на текущих и на новых клиентов, количество звонков в кол-центр может увеличиться. Есть риск, что возрастным людям будет непросто сориентироваться в новых процессах и они захотят уточнить условия открытия депозита по телефону.

## Проблема и предложения

В ходе анализа проблемы сотрудники банка внесли несколько предложений:

1. **Нужно, чтобы сотрудники кол-центра могли проконсультировать клиентов хотя бы по текущим ставкам банка.** Для этого надо каким-то образом предоставить их системе доступ к ставкам по депозитам.

2. **Есть риск, что кол-центр будет перегружен.** Поэтому необходимо подключить к работе партнёрский кол-центр. При этом важно, чтобы сотрудники партнёрского кол-центра также могли проконсультировать клиентов по актуальным депозитным ставкам.

3. **Для этого нужно наладить процесс передачи информации об актуальных ставках между банком и кол-центром.** Кол-центр партнёра работает во внешней информационной системе относительно банка. Они готовы получать актуальные ставки в виде файлов. Нет возможности сделать API-вызовы (например, через SFTP-протокол).

Все эти изменения необходимо учесть в MVP и предложить решение на основе текущего процесса работы со ставками.

## Ключевые особенности решения

### Архитектурные принципы:
1. **Безопасность** - шифрование всех каналов передачи данных
2. **Надежность** - резервирование каналов и автоматическое восстановление
3. **Совместимость** - использование существующих технологий кол-центров
4. **Мониторинг** - полный контроль процесса передачи данных

### Технологический стек:
- **Система передачи ставок:** .NET Core
- **SFTP-сервер:** OpenSSH
- **API для кол-центра:** REST API
- **Мониторинг:** Prometheus + Grafana
- **База данных:** MS SQL

### Критерии успеха:
- **Технические:** Время обновления ставок < 5 минут, доступность 99.5%
- **Бизнес:** Снижение нагрузки на кол-центр на 30%, улучшение качества консультаций

### Риски и митигация:
- **Высокие риски:** Проблемы с безопасностью, перегрузка кол-центров
- **Митигация:** Шифрование файлов, подключение партнерского кол-центра, резервирование каналов

## Команды разработки

1. **Backend-команда** - разработка системы передачи ставок, интеграция с кол-центрами
2. **DevOps-команда** - настройка SFTP-сервера, мониторинга, автоматизация
3. **QA-команда** - тестирование безопасности, производительности, интеграций
